## 📋 ISSUES ANALYZED

### 1. ❌ Message Deletion Failing (400 Error)
**Symptom**: `Failed to load resource: the server responded with a status of 400 () - invalid input syntax for type uuid`

**Root Cause**: 
- sidepanel.js generates custom message IDs: `post-1760723851042-ms25fdtof`
- Supabase messages table expects UUID format
- When deletion attempts to match on `id` field, Supabase rejects non-UUID format

**Fix Applied**: ✅
- Modified `sendMessage()` in `supabase-realtime-client.js` to return the UUID generated by Supabase
- Updated `sendMessageViaSupabase()` in `sidepanel.js` to capture and return the message data
- Modified message creation to use the Supabase UUID instead of custom ID format

### 2. ❌ Avatar Inconsistencies
**Symptom**: Avatars showing differently across clients, not propagating correctly

**Root Cause**:
- `user_presence` table schema missing `avatar_url` column
- System can't store/propagate real avatar URLs via real-time subscriptions
- Clients fall back to generic avatars because no URL is transmitted

**Fix Applied**: ✅
- Created SQL script to add `avatar_url` column to `user_presence` table
- Modified `updatePresence()` to save avatar URLs when available
- Enhanced avatar detection logic to find real Google avatars from multiple sources

### 3. ⚠️ Visibility System Issues
**Symptom**: Users not showing as "visible" when on same page, no "last seen" messages

**Status**: Needs Further Investigation
- Real-time subscriptions are working (confirmed by logs)
- Event handlers are configured correctly
- UI update logic may have issues with `refreshVisibilityAvatars()`

### 4. ⚠️ Message Propagation UI Issues
**Symptom**: Messages sent but not appearing in real-time for other users

**Status**: Needs Further Investigation
- Messages are being inserted into Supabase (confirmed)
- Real-time events are firing (confirmed)
- UI update function `addMessageToChat()` needs verification

### 5. ✅ Aura Color Propagation (Previously Fixed)

## 🗄️ DATABASE CHANGES REQUIRED

### CRITICAL: Run this SQL on your Supabase database

**File**: `/home/ubuntu/fix-supabase-schema.sql`

```sql
-- 1. Add avatar_url column to user_presence table
ALTER TABLE user_presence 
ADD COLUMN IF NOT EXISTS avatar_url TEXT;

-- 2. Add performance indexes
CREATE INDEX IF NOT EXISTS idx_user_presence_user_email ON user_presence(user_email);
CREATE INDEX IF NOT EXISTS idx_user_presence_page_id ON user_presence(page_id);
CREATE INDEX IF NOT EXISTS idx_messages_page_id ON messages(page_id);
CREATE INDEX IF NOT EXISTS idx_messages_user_email ON messages(user_email);

-- 3. Create user_visibility table if it doesn't exist
CREATE TABLE IF NOT EXISTS user_visibility (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_email TEXT NOT NULL,
  page_id TEXT NOT NULL,
  page_url TEXT NOT NULL,
  is_visible BOOLEAN DEFAULT true,
  last_activity TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(user_email, page_id)
);

-- 4. Enable RLS and policies
ALTER TABLE user_visibility ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow all operations" ON user_visibility FOR ALL USING (true);

-- 5. Add to real-time publication
ALTER PUBLICATION supabase_realtime ADD TABLE user_visibility;

-- 6. Auto-update timestamps
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ language 'plpgsql';

DROP TRIGGER IF EXISTS update_user_presence_updated_at ON user_presence;
CREATE TRIGGER update_user_presence_updated_at 
BEFORE UPDATE ON user_presence 
FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();
```
