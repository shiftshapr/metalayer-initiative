# CRITICAL RED-LINE ENFORCEMENT

## Source-Only Editing Policy (MANDATORY)

**THIS IS A RED-LINE RULE - VIOLATIONS CAUSE LOST WORK AND BUILD INCONSISTENCIES**

### ⛔ PROHIBITED ACTIONS:
- ❌ **NEVER edit files directly in `extension/`, `dist/`, or `build/` directories**
- ❌ **NEVER edit JavaScript files that are compiled from TypeScript**
- ❌ **NEVER make "quick fixes" in build artifacts**
- ❌ **NEVER manually copy files to `extension/` or `dist/`**

### ✅ REQUIRED WORKFLOW:
1. **ONLY edit TypeScript source files in `src/`**
2. **Run the build process**: `npm run build:presence` (or equivalent)
3. **Verify changes**: Check that `dist/` and `extension/` are updated from `src/`

### 🚨 IF YOU FIND YOURSELF EDITING `extension/` OR `dist/`:
1. **STOP IMMEDIATELY**
2. **Find the corresponding `src/` file**
3. **Edit the TypeScript source file instead**
4. **Run the build process**

### 📋 EXCEPTIONS:
- **Hand-authored JS files**: Some files are intentionally JavaScript (not TypeScript). These are listed in build scripts. Only edit these if explicitly marked as hand-authored.
- **If unsure**: Check if a file exists in `src/` - if it does, edit that. If it doesn't, check build scripts to see if it's hand-authored.

### 🔍 HOW TO IDENTIFY SOURCE FILES:
- ✅ **Edit these**: Files in `src/` directory (`.ts`, `.tsx` files)
- ❌ **Don't edit these**: Files in `extension/`, `dist/`, or `build/` directories (`.js` files that are compiled)

### ⚠️ ENFORCEMENT:
- This rule is enforced in:
  - System prompt (this file)
  - `.cursorrules` files
  - JAUmemory (stored as critical redline)
- Violations will cause:
  - Lost work (edits get overwritten on rebuild)
  - Build inconsistencies
  - Extension failures

### 📝 REMINDER:
**Before making ANY edit, ask yourself: "Am I editing a file in `src/`?" If the answer is NO, STOP and find the source file.**
